The following table specifies the constraints on each CloudEvents context attribute for a CS API Resource Event.

[#cloudevents-properties-table,reftext='{table-caption} {counter:table-num}']
.CloudEvents Context Attributes for Resource Events
[width="100%",options="header"]
|====
| *Attribute*       | *Value / Constraint*
| `specversion`     | Fixed value `1.0`.
| `type`            | A string identifying the affected resource type and the operation that took place. See <<resource-event-types-table>>.
| `source`          | An absolute URI identifying the CS API context. Use the associated HTTP API root URL when available; otherwise use a stable context URI.
| `subject`         | The canonical resource URL when exposed by an associated CS API HTTP service; otherwise a stable absolute URI identifying the resource.
| `id`              | A non-empty, producer-defined string that, together with `source`, uniquely identifies each distinct event. Producer-maintained counters and UUIDs are valid examples.
| `parentId`        | _(extension)_ The parent resource identifier, using its canonical URL when exposed by an associated CS API HTTP service, or a stable absolute URI otherwise (e.g. the parent `System` when a subsystem is created). Recommended whenever applicable.
| `time`            | The timestamp of the resource operation. Ideally the moment the resource becomes visible to API clients; alternatively, the time the originating request was received or processed by the server.
| `datacontenttype` | Required only when `data` is included. SHALL be `application/json`.
| `data`            | _Optional._ When present, a JSON object summarizing the affected resource. Contains at least the resource's `name` and `description` properties when those are defined on the resource. Additional properties MAY be included.
|====

[#resource-event-types-table,reftext='{table-caption} {counter:table-num}']
.Resource Event Types
[width="100%",options="header"]
|====
| *Event Type*                                | *Description*
| `org.ogc.api.csapi.<resource>.create`      | A resource of the given type was created.
| `org.ogc.api.csapi.<resource>.update`      | A resource of the given type was replaced or updated.
| `org.ogc.api.csapi.<resource>.delete`      | A resource of the given type was deleted.
|====

[[resource-event-identity]]
=== Resource identity in standalone deployments

A CS API context identifies the logical resource service in which operations occur, independently of the broker or processes delivering its events. The `source` URI identifies that context, `subject` identifies the affected resource, and the parent extension identifies the parent resource. These identifiers are distinct from the event's `id`, transport channel addresses, and any UID identifying a real-world entity in a resource representation.

An implementation can provide Resource Events without an associated CS API HTTP service. In that case, absolute URIs such as UUID URNs provide stable identifiers without implying an HTTP retrieval operation. When an associated HTTP service exposes a resource, its canonical resource URL is used instead. A resource URI used in a deletion event remains the identifier of the deleted resource even though it no longer resolves to a representation. The resource model and applicable encoding requirements still apply.

In this example:

* `source` identifies the logical CS API deployment, not the broker, a publisher process, or an individual sensor. Its configured value is retained across restarts and broker migrations; a new source UUID is not generated for each event.
* `subject` identifies this particular System resource. Later update or deletion events for the same System use the same subject URI. Other resources have different subject URIs, even when their events share the same source.
* `id` identifies this event within the source context. A different event receives a different event ID; retransmission of the same event may retain its ID.

The UUIDs shown are illustrative. Each deployment assigns its own identifiers. These URNs require neither an HTTP server nor a service that resolves them to network locations.
